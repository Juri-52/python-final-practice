# 課題3：駐車場の動作をシナリオでテストしよう

駐車場の管理プログラムを引き継ぎました。車の入庫・出庫、空きスペース、売上を管理します。しかし、配布されたクラスには状態管理の誤りがあります。利用者が実際に行う操作をテストで再現し、問題を見つけて修正してください。

今回は料金の数字だけでなく、**操作の戻り値、駐車中の車、売上、失敗後の状態**を確認します。

## ファイル

| ファイル | 役割 |
| --- | --- |
| parking.py | 完成済みの料金計算と、修正対象のParkingLot |
| test_parking.py | 自分で完成させる6つのテスト |
| main.py | 完成済みの動作確認用シナリオ |

calculate_fee()の計算は正しいものとして使います。修正するのはParkingLotです。テストの期待値やmain.pyを誤った実装に合わせて変更しないでください。

## ParkingLotの仕様

| 属性 | 型 | 意味 |
| --- | --- | --- |
| capacity | int | 駐車できる最大台数 |
| cars | list[str] | 現在駐車している車の番号。初期値は空リスト |
| revenue | int | この駐車場の売上。初期値は0 |

capacityは正の整数、車の番号は空でない文字列、hoursは0以上の整数とします。入力値の検証や例外処理の追加は不要です。

### enter(car_number) -> bool

- 同じ車がすでに駐車している場合はFalseを返します。
- 満車の場合もFalseを返します。
- 入庫できる場合はcarsに番号を1件追加し、Trueを返します。
- 入庫時に売上は増えません。失敗した場合はどの属性も変更しません。

### leave(car_number, hours) -> int | None

- 駐車していない車ならNoneを返し、状態は変更しません。
- 駐車している車ならcalculate_fee()で料金を求め、carsからその車を削除します。
- その料金をrevenueに加え、料金を返します。
- 出庫後は別の車がその場所を使えます。同じ車を再び出庫させても料金を取りません。
- **0は無料で出庫できたこと、Noneは出庫できなかったことを表します。**

各インスタンスは独立したcarsとrevenueを持ちます。メソッド内ではprintしません。

料金は0時間なら0円、最初の1時間は300円、以降1時間ごとに100円を追加し、上限1000円です。料金をParkingLot内で再計算せず、既存の関数を利用します。

## 1. 準備・操作・確認の順にテストを書く

1. **準備（Arrange）**：テスト内で新しいParkingLotを作り、必要な車を入庫させます。
2. **操作（Act）**：確認したいメソッドを呼び、戻り値を変数に保存します。
3. **確認（Assert）**：戻り値と、操作後のcars・revenueをassertで確認します。

複数の操作を行うテストでは、途中の状態も確認します。単にassertを増やすのではなく、「入庫できたが車が登録されていない」「失敗したのに売上が増えた」などの不具合を検出できる確認を書きます。

テスト同士でオブジェクトを共有しません。input、実際のファイル、printの目視確認は不要です。特別なfixtureやmockも不要です。

## 2. 作成する6つのテスト

### ① 入庫 → 支払い → 出庫 → 次の車

関数：test_visit_records_payment_and_frees_space

容量1の駐車場にA-001を入庫させます。True、carsがA-001だけ、売上0を確認します。3時間で出庫させ、料金500、carsが空、売上500を確認します。続けてB-002を入庫させ、True、carsがB-002だけ、売上は500のままであることを確認します。

### ② 満車時は状態を変えない

関数：test_full_parking_rejects_another_car

容量2にA-001、B-002を入庫させた後、C-003を入庫させます。False、carsが元の2台のまま、売上が変わらないことを確認します。

操作前のリストを保存する場合はcopy()でコピーします。同じリストへの参照だけを保存すると、変更前の状態との比較になりません。

### ③ 同じ車は二重に入庫できない

関数：test_duplicate_entry_does_not_use_another_space

容量3にA-001を入庫させ、空きがある状態で同じ番号を再び入庫させます。False、carsがA-001の1件だけ、売上0を確認します。満車だから失敗するケースとは分けてください。

### ④ 駐車していない車の出庫

関数：test_unknown_car_cannot_leave

容量2にA-001が駐車している状態で、Z-999を3時間として出庫させます。戻り値がNone、A-001が残っていること、売上0を確認します。

### ⑤ 無料の出庫と二重請求の防止

関数：test_free_exit_cannot_be_charged_again

容量1にA-001を入庫させ、0時間で出庫させます。戻り値0、Noneではないこと、carsが空、売上0を確認します。続けて同じ車を3時間として再び出庫させます。今度はNoneとなり、carsと売上が変わらないことを確認します。

### ⑥ 2つの駐車場は独立している

関数：test_parking_lots_have_independent_state

容量1の駐車場を2つ作ります。1つ目にA-001を入庫させても、2つ目は空で売上0のままであることを確認します。2つ目にB-002を入庫させ、1つ目のA-001を1時間で出庫させます。1つ目は料金300・空・売上300、2つ目はB-002が残り売上0であることを確認します。

## 3. テストを使って修正する

このフォルダー内で実行します。

```bash
python3 -m pytest -q
```

まず6つのテストを完成させ、配布されたクラスで失敗するテストを確認します。passだけのテストが成功しても、動作を検証したことにはなりません。

その後、ParkingLotを修正します。失敗条件は状態の変更前に判定し、早期リターンで整理します。料金計算は既存関数に任せ、同じ計算を複製しません。最後に、実際のassertを含む6つのテストが成功することを確認してください。
